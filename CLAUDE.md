# Diamond Story

Match-3 mobile game (portrait) in Kotlin on libGDX. Targets Android and iOS; the desktop module exists only for development.

## Build & run

There is no system `java` on the dev machine. Every Gradle call needs JAVA_HOME:

```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@21
./gradlew desktop:run                               # play on desktop (window 540x960)
./gradlew core:build desktop:build ios:compileJava  # full compile check
```

- The `android` module is included only when an Android SDK is configured (`sdk.dir` in `local.properties` or `ANDROID_HOME`); see `settings.gradle`. Without one, `:android` tasks do not exist. That is expected, not an error.
- iOS (RoboVM/MobiVM) compiles anywhere, but launching (`ios:launchIPhoneSimulator`) needs full Xcode.
- All versions are in `gradle.properties`. When upgrading, copy the combination currently generated by gdx-liftoff (https://github.com/libgdx/gdx-liftoff); it is a tested set.
- There are no automated tests. Verify changes by running `desktop:run` and playing a match.

## Hard constraints

- **Java 8 bytecode only**: RoboVM does not support newer bytecode. Kotlin `jvmTarget` is 1.8 and Java uses `release 8`. Do not raise these, and do not use JDK 9+ APIs in `core`.
- Launchers (`desktop/`, `android/`, `ios/`) are Java and instantiate `DiamondStoryGame()`. It is a class, not an `object`.
- Sources use the flat `src/` layout (not `src/main/kotlin`). Core packages are top-level (`screens`, `gameobjects`, `utils`, ...), not under `com.alextriukhan`.

## Assets

- `android/assets/` is a **separate git repository** (diamond-story-assets) and is git-ignored here. Never commit assets into this repo. All platforms read assets from this folder.
- Atlases are packed with TexturePacker (`graphics/PackerProject.tpproj`). Region names must match the `findRegion(...)` calls in `utils/GameScreenAssets.kt`.
- The assets repo also contains `src/` (.xcf sources) and loose PNGs. Only atlases, `effects/`, `fonts/`, `levels/`, `skin/` are used at runtime; `src/` and `*.tpproj` are excluded from packaging.
- `skin/glassy-ui.*` is the third-party Glassy UI skin (CC BY 4.0, credit in README).
- Every asset is loaded through the shared `AssetManager`:
  - load it in `LoadingScreen.setToLoad...Resources()`;
  - get it in `GameScreenAssets` / `GlobalAssets`;
  - unload it in `GameScreen.disposeResources()`.

  Missing any of these steps causes a crash or a leak.

## Code map

- `DiamondStoryGame`: owns the `AssetManager` and a stack of screens (`MyStack<Screen>`). Flow: `LoadingScreen` -> `MainMenuScreen` -> `LoadingScreen(GAME_SCREEN)` -> `GameScreen`.
- `gameobjects/GameGrid.kt`: all match-3 logic (swaps, match detection, falling, specials, score). It is the largest and most fragile file.
- Levels are `levels/lN.json`, deserialized into `Level` by libGDX `Json` with `ignoreUnknownFields = true`. `l1.json` still has old `posX/posY` objective fields, while `Objective` currently has `count`.

## Gotchas

- Grid templates are arrays of **columns**, not rows: `cells[x][y]`, with `y = 0` at the bottom. `GameGrid.MAX_ROWS` is actually the column count.
- Layout is computed once from `Gdx.graphics.width/height` at construction, with 520px as the reference width for scaling fonts and particles. Runtime resize is not really supported.
- Kotlin 2.x requires `when` over enums to be exhaustive. Add explicit no-op branches rather than `else` so new enum values surface as compile errors.
- `LoadingScreen` prints `Percentage: ...` every frame, so filter stdout when reading logs.
- On macOS, LWJGL3 needs `-XstartOnFirstThread`. The Gradle `run` task adds it; an IDE run configuration for `DesktopLauncher` needs it added manually.
